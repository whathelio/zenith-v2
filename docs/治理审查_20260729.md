## 四、分流逻辑审计 — smart_classify 的"双重蒸馏"问题

### 当前流程（2 次 LLM 调用）

```
用户输入 → smart_classify [LLM调用1]
  ├─ 分类: is_plan=true, is_thought=false
  ├─ 创建 raw note (nid=58)  ← 95% 的情况这条记录无用
  └─ _distill_raw_note(58) [LLM调用2]
       ├─ 检索相关偏好/方法
       ├─ LLM 决定: schedule.should_create=true
       └─ 创建日程，标记 note.distilled_into=[schedule_id]
```

### 目标流程（1 次 LLM 调用）

```
用户输入 → unified_classify [LLM调用1]
  ├─ 分类 + 动作判断（一次完成）
  ├─ 直接创建 schedule/memory/refined_note（不经过 raw note）
  └─ 0 次中间产物
```

**收益：** 每次日程/笔记触发节省 1 次 LLM 调用。按 30 条已完成的日程计算，已浪费约 50+ 次不必要的 LLM 调用。
