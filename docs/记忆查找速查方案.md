# 记忆查找速查方案 — 在对话中定位记忆

> 目的：在对话里快速、准确地找到某条记忆，不靠猜。
> 适用：当前 Zenith 对话（search_memory / edit_memory / delete_memory 已就绪）。

---

## 一、三种查找方式（按推荐顺序）

### 方式 1：编号直达（最准，推荐）
记忆有独立编号后，对话里直接说编号：

```
"查一下 TM-007 这条记忆"
"把 AIM-003 的内容给我"
"编辑 TM-002，改成：XXX"
```

编号体系：
| 前缀 | 含义 | 示例 |
|------|------|------|
| TM | 交易/金融/经济 | TM-001 ~ TM-021 |
| AIM | AI/编程/技术 | AIM-001 ~ AIM-024 |
| PM | 私密/安全 | PM-001 ~ PM-007 |
| MM | 方法论/元认知 | MM-001 ~ MM-005 |

> ⚠️ 编号落地实施中（memories 表 code 字段）。**落地前**用方式 2。

### 方式 2：关键词搜索（当前可用）
对话里描述记忆内容，用**核心词**而不是口语长句：

```
"搜索记忆：每日交易复盘"
"我有没有关于日本泡沫经济的记忆？"
"查一下量化宽松"
```

技巧（实测有效）：
- ✅ 用原文里的**准确词**：`"量化宽松"`、`"期货黄金交易三套规则"` → 命中率高
- ❌ 用口语模糊词：`"炒作"`、`"那个经济泡沫的事"` → 可能 0 命中
- 组合词更准：`"复盘 成交量"`（空格分隔多关键词）

### 方式 3：按类型浏览（当前可用）
对话里要求按类型列出，适合"想不起来关键词"时：

```
"列出所有交易相关的记忆"
"有哪些技能类记忆？"
"查一下经验类的记忆"
```

支持类型：personal_info（个人信息）/ preference（偏好）/ event（事件）/ decision（决定）/ fact（事实）/ experience（经验）/ skill（技能）

---

## 二、找到之后：确认 → 修改 / 删除

找到的记忆会以「记忆卡片」形式展示（含 ID、类型、内容、关键词、重要性）。

### 修改
```
"修改记忆 #1650，内容改成：XXX"
"给记忆 313 加上关键词：复盘"
```
→ 生成**待确认请求**，你在左侧「📋 待确认提议」点 ✓ 才生效。

### 删除
```
"删除记忆 #1650"
```
→ 同样**待确认**后才真删，不会误删。

### 查 ID（确认是哪条）
对话里问"这条记忆的 ID 是多少"，或展开记忆卡片直接看。

---

## 三、查找不到时的排查顺序

1. **换关键词**：从口语改成记忆原文里的准确词（如 `复盘` → `每日交易复盘`）
2. **换类型过滤**：缩小范围（fact vs experience vs decision）
3. **直接问**："把我 8 月 6 日之前存的交易相关记忆都列出来"
4. **确认记忆是否被蒸馏合并**：蒸馏可能把多条合并成一条，内容变了关键词可能失效

---

## 四、对话话术模板（可直接复制）

| 场景 | 话术 |
|------|------|
| 按编号查 | `查一下 TM-007 这条记忆` |
| 按内容搜 | `搜索记忆：日本泡沫经济核心引擎` |
| 按类型看 | `列出所有 fact 类型的记忆` |
| 修改 | `修改记忆 #313 的内容为：每天复盘一次交易并记录错误` |
| 改重要性 | `把记忆 #1966 的重要性改成 5` |
| 删除 | `删除记忆 #313，我确认过了` |
| 查编号对应 | `TM-007 对应的是哪条记忆？` |

---

> 维护：编号体系落地（code 字段）后，本方案自动升级为"编号直达"为主，无需改话术。
