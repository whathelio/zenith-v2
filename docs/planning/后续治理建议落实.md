## 2. 目标状态灰度收敛方案

### 2.1 原则
- **不一次性删除本地 state**。
- 每步只替换一个页面的数据源，验证刷新/更新后再下一步。
- 每步都可回滚（git checkout 单文件）。

### 2.2 步骤

| 步骤 | 改动 | 验证 | 回滚 |
|------|------|------|------|
| **S1** | `CalendarView` 删除本地 `fullGoals/goalStats/loadGoals`，改用 `useCalendarGoal()` | 1) 进入 `/calendar` 能看到目标；2) 标记今日后左侧面板和主日历同步刷新；3) 编辑目标后两处一致 | `git checkout features/CalendarView.tsx` |
| **S2** | `GoalsView` 删除本地 `goals/stats/loadGoals`，改用 Context | 1) `/goals` 列表正常；2) 创建/编辑/删除后左侧面板和主日历同步 | `git checkout features/GoalsView.tsx` |
| **S3** | `AppLayout` 把 `goalDisplayField` 放进 Context；左侧面板和 `GoalTrackerPanel` 都消费 | 1) 切换显示字段，左侧和主日历数值都变；2) 无残留本地 state | `git checkout contexts/CalendarGoalContext.tsx components/AppLayout.tsx` |
| **S4** | 激活日期操作收敛到 `GoalDetailModal`；`GoalTrackerPanel` 的“标记今日”改为打开弹窗 | 1) 只有一个入口改激活日；2) 左侧/主日历圆点同步 | `git checkout features/CalendarView.tsx` |

### 2.3 验收
- 三个页面共用一份数据源，`api.listGoals()` 只在 `AppLayout` 调一次。
- 任意页面更新目标后，其他页面无需手动刷新。
- `goalDisplayField` 切换全局生效。

## 3. /knowledge 页面验收标准

### 3.1 功能验收

| 编号 | 场景 | 预期行为 | 通过标准 |
|------|------|----------|----------|
| K1 | 上传 PDF | 解析进度条 → 入库完成提示 | 30 秒内单篇完成，`kb_stats` 片段数 +N |
| K2 | 提问检索 | 返回答案 + 引用卡片 | 答案含 `[来源: ...]`，点击卡片能打开原文路径 |
| K3 | RAG → Wiki 跳转 | 引用卡片有“加入 Wiki”按钮 | 点击后调用 `compile_wiki_page`，生成页面并在 Wiki 列表可见 |
| K4 | 长任务异步 | 复杂问题走 `/tasks` | 立刻返回 task_id，页面显示“思考中”，完成后展示结果 |
| K5 | 任务状态查询 | 刷新页面能看到任务历史 | `/tasks` 列表显示 done/failed 与结果 |
| K6 | 无结果兜底 | 问知识库没有的内容 | 明确回答“知识库中未找到相关内容” |
| K7 | OCR 回退 | 上传扫描件 PDF | 覆盖率 <80% 时提示需 OCR，或装了 OCR 后自动回退 |
| K8 | 健康检查 | `/api/knowledge/health` | 返回 `{status: ok}` |

### 3.2 非功能验收
- 页面加载 < 2 秒（无索引时）
- 检索响应 < 8 秒（本地 Chroma + DeepSeek API）
- 长任务不阻塞 UI
- API 鉴权：无 token 返回 401

## 4. 微信通道延后确认

用户决定：**微信/OpenClaw 通道在 UI 和知识库基座稳固后再接**。

### 理由记录
- 当前 `api_gateway` + `task_worker` 已就绪，但前端 `/knowledge` 未建，目标 UI 未收敛。
- 微信通道接入后调试面会从 1 个（Web）变成 2 个（Web + 微信），在基座不稳时调试痛苦翻倍。
- 建议顺序：**目标 UI 收敛 → /knowledge 页面 → 后端集成 → 微信通道**。

### 触发条件
满足以下 3 条后再开始微信通道：
1. 目标状态灰度收敛完成（S1–S4 全部通过）。
2. `/knowledge` 页面 K1–K6 验收通过。
3. `knowledge_service.py` + `/api/knowledge/*` 端点上线并可被 Zenith 前端调用。
